# dev-assistant

A plug-and-play AI assistant for any software project.

Connect it to your codebase once and get:

- **Implementation planning chatbot** — describe a new feature, get exact file paths, implementation order, and impact map
- **Change impact analysis** — ask what will break before you change anything
- **Codebase Q&A** — plain English answers about how your project works
- **AI context workflows** — auto-generate feature docs, gap analysis, and Claude memory files

Built on [graphify](https://pypi.org/project/graphifyy/) — maps your entire codebase into a queryable knowledge graph.

---

## Quick start

### 1. Install prerequisites (once per machine)

```powershell
# Windows
.\install.ps1

# Mac / Linux
chmod +x install.sh && ./install.sh
```

This installs **Python**, **graphify**, and checks for the **Claude CLI** (Claude Code subscription required).

### 2. Connect to your project (once per project)

```powershell
# Windows
.\connect.ps1

# Mac / Linux
./connect.sh
```

The script will ask you:
- Path to your project
- Tech stack
- Architecture rules
- Golden module reference files
- Existing features

Then it builds the knowledge graph and writes `config.json`.

### 3. Start the assistant

```powershell
python server.py
```

Open **http://localhost:8765** in your browser.

## AI context workflows

Run these inside **Claude Code** chat to generate or update documentation:

### Update full project memory (all features)

```
Workflow({ name: 'update-project-memory', args: { date: '2026-06-28' } })
```

Scans every feature in your codebase and writes memory files to `~/.claude/projects/<your-project>/memory/`. Claude Code loads these automatically in future sessions.

### Generate docs for one feature

```
Workflow({ name: 'feature-docs', args: { feature: 'Invoice Management', date: '2026-06-28' } })
```

Writes to `docs/specs/` in your project:
- `invoice-management-spec.md` — full requirements spec
- `invoice-management-acceptance.md` — Given/When/Then scenarios
- `invoice-management-ui-map.md` — UI component mapping
- `invoice-management-gap-analysis.md` — what's done vs what's missing

See `COMMANDS.md` (generated by connect.ps1) for pre-filled commands with your project's paths.

### Export docs as PDF / DOCX

Add `formats` to the `feature-docs` call to also generate PDF/DOCX versions of the four docs above:

```
Workflow({ name: 'feature-docs', args: { feature: 'Invoice Management', formats: ['pdf', 'docx'] } })
```

Or convert any already-generated Markdown docs manually, any time:

```bash
cd /path/to/your/project
python docs_export.py "docs/specs/invoice-management-*.md" --formats pdf,docx
```

`docs_export.py` and its dependencies (`markdown`, `xhtml2pdf`, `python-docx`) are installed by `install.ps1` / `install.sh` and copied into your project by `connect.ps1` / `connect.sh`.

## Coding skills installed into every connected project

`connect.ps1` / `connect.sh` also copy a set of Claude Code skills into `.claude/skills/` in the connected project. They're auto-discovered by Claude — no slash command needed:

| Skill | What it does |
|-------|---------------|
| `regression-guard` | Graphify-powered regression gate that ensures new changes never break existing caller contracts |
| `live-context-verifier` | Forces AI to fetch the latest graphify codebase graph and dependent modules before touching code |
| `senior-engineer-mindset` | Enforces 10+ year veteran discipline: minimal surgical changes, zero scope creep, and maximum reuse |
| `grill-me` | Adversarial, one-question-at-a-time requirements interview before any design/code starts |
| `context-loader` | Loads this project's real architecture rules + closest reference module before coding |
| `pattern-clone` | Clones an existing module's structure instead of inventing a new pattern |
| `db-design` | Schema/migration/index planning, grounded in this project's actual DB tooling |
| `code-review-quality` | Duplicate/dead-code/architecture/security review gate before calling a task done |
| `test-agent` | Builds and runs an acceptance-criteria test matrix, detecting this project's real test tooling |

All of them read project context the same way `grill-me` does: a connected dev-assistant `config.json` first, falling back to `CLAUDE.md`/`AGENTS.md`/architecture docs already in the project — never a hardcoded assumption about the stack.

### Multi-agent adapters (Cursor, Copilot, Gemini, Codex)

The same skills are also fanned out to other AI coding tools' native formats, so the rules apply no matter which agent a teammate uses:

- Cursor → `.cursor/rules/<skill>.mdc`
- GitHub Copilot → `.github/instructions/<skill>.instructions.md`
- Gemini → `GEMINI.md` (marked section per skill)
- Codex → `AGENTS.md` (marked section per skill)

This runs automatically at connect time. To re-run it by hand (e.g. after editing a skill):

```bash
python generate_agent_adapters.py --project-root /path/to/your/project
```

It's idempotent — re-running it updates each skill's section in place instead of duplicating it, and leaves any hand-written content in `GEMINI.md`/`AGENTS.md` untouched.

## How it works

```
Your project
    └── graphify-out/
            └── graph.json      ← 5000+ nodes, auto-built by connect.ps1

dev-assistant/
    ├── config.json                    ← your project config (gitignored)
    ├── server.py                      ← reads config, runs chatbot
    ├── docs_export.py                 ← copied into your project by connect.ps1, converts .md docs to PDF/DOCX
    ├── generate_agent_adapters.py     ← fans .claude/skills out to Cursor/Copilot/Gemini/Codex formats
    ├── templates/skills/              ← copied into your project's .claude/skills/ by connect.ps1
    │       ├── grill-me/
    │       ├── context-loader/
    │       ├── pattern-clone/
    │       ├── db-design/
    │       ├── code-review-quality/
    │       └── test-agent/
    └── workflows/                     ← copied into your project by connect.ps1
            ├── update-project-memory.js
            └── feature-docs.js
```

When you ask a question:
1. `server.py` detects intent (plan / impact / explain)
2. Runs targeted `graphify query` commands against your graph
3. Sends graph context + your project rules to Claude
4. Returns a structured answer with exact file paths

## Keeping the graph fresh

After code changes, rebuild the graph:

```bash
cd /path/to/your/project
graphify . --backend claude-cli
```

Or install auto-rebuild git hooks (rebuilds after every commit):

```bash
graphify hook install
```

---

## Connecting to a different project

Run `connect.ps1` again — it overwrites `config.json` with the new project's settings. You can maintain multiple configs by renaming: `config.lims.json`, `config.crm.json`, etc., and symlinking the one you want as `config.json`.
